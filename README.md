# 교내 카페 사전 주문 · 화면설계서와 기능명세서 + Live Demo

**Live Demo: https://campus-cafe-preorder-spec.vercel.app**

잇타 10기 기획 스터디 3주차 과제. 쉬는 시간에 주문이 몰리는 교내 카페에서, 학생이 **주문 전에 ‘지금 시키면 언제 받는지’를 보고 다음 수업 전에 받을 수 있는지 직접 판단**하게 하는 사전 주문 서비스의 화면·기능 정의서와 실제로 눌러 볼 수 있는 시연 화면입니다.

## 메뉴 구성

| 메뉴 | 내용 |
| --- | --- |
| 전체 흐름 보기 (`#/flow`) | 화면 6개(화면 5 + 팝업 1) 카드 · 정적 미리보기 · 공통 컴포넌트 · 확인 필요 목록 |
| 문서 보기 (`#/docs/S-01`) | 화면 개요 → 화면 설명 → 큰 프레임 + 번호별 구성 요소 → 기능명세. 첫 진입 화면 |
| 시연하기 (`#/demo/S-01`) | 실제 버튼 · 입력 · 상태 변화로 동작하는 서비스 화면 + 시연 컨트롤 |

문서와 시연은 서로 연결 버튼 없이 상단 메뉴와 전체 흐름 카드로 각각 들어갑니다.

## 2주차 피드백 반영

1. 장바구니 진입 경로: 홈 우측 상단 장바구니 아이콘(개수 배지), 홈 · 메뉴 목록 하단 장바구니 바(C-03), 담기 직후 ‘보기’ 토스트
2. 공통 컴포넌트: C-01 예상 수령 시각 표시(L/S/M), C-02 메뉴 아이템 카드(목록형/최근 주문형/장바구니형/요약형), C-03 장바구니 바, C-04 하단 탭 바 → `src/service/parts.tsx`

## Mock 범위

실제 서버 · 결제 · 푸시 연동은 없습니다.

- 대기열: 앞선 주문 8건(제조 시간 합 22분), 동시 제조 인원 2명 → 시작 시 ‘약 12분 뒤 · 오후 2:47’
- 시계: 오후 2:35에서 시작해 실제 시간만큼 흐름. 30초마다 예상 시각 갱신
- 결제: 0.9초 뒤 성공(시연 컨트롤로 실패 재현). 주문번호 A-127부터
- 알림: 실제 푸시 대신 앱 안 상단 배너
- 장바구니 보관: 명세는 계정 기준 서버 저장이지만 시연은 이 브라우저 localStorage
- 매장 · 다른 학생 쪽 이벤트(주문 추가, 제조 완료, 조회 실패)는 시연 컨트롤 버튼으로 대신 발생

## 개발자용 실행 방법

```bash
npm install
npm run dev     # 개발 서버
npm run build   # dist/ 생성
npm run lint
```

React + Vite + TypeScript + Tailwind CSS. 해시 라우팅(`#/docs/S-03`)이라 새로고침 · 직접 URL 진입에 별도 서버 설정이 필요 없습니다.

매핑과 QA 결과는 [`docs/MAPPING.md`](docs/MAPPING.md)에 있습니다.
